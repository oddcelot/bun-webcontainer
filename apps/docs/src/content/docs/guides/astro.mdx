`@runbun/astro` adds code blocks to an Astro 7 site that are highlighted at build time with [@pierre/highlights](https://diffs.com/highlights) and turn into a live [embed](/guides/embedding/) when a reader clicks Run. Until then a block is plain HTML: no script runs and nothing downloads. The examples below show each source and, under it, what it renders.

```sh
bun add @runbun/astro
```

## Set up

Add the integration, and the remark plugin if you want runnable fences in Markdown and MDX:

```js
// astro.config.mjs
import { defineConfig } from "astro/config";
import { unified } from "@astrojs/markdown-remark";
import runbun from "@runbun/astro";
import remarkRunbun from "@runbun/astro/remark";

export default defineConfig({
  integrations: [runbun()],
  markdown: { processor: unified({ remarkPlugins: [remarkRunbun] }) },
});
```

## Code blocks

In `.mdx` or `.astro` files, `<Code>` renders a block. On its own it stays static: highlighted HTML and CSS, with no request of its own and one small script, for its Copy button. Its styles go into the page's own stylesheet, once however many blocks the page has.

```mdx
import { Code } from "@runbun/astro/components";

<Code lang="ts" title="greet.ts" code={`export const greet = (name: string) => "Hello, " + name;`} />
```

<Code lang="ts" title="greet.ts" code={`export const greet = (name: string) => "Hello, " + name;`} />

`playground` adds the Run button. The block takes every embed option (`mode`, `features`, `files`, `path`, `layout`, `readonly`, `persist`, `expand`, …), and `title` names the file:

```mdx
<Code
  playground
  mode="code"
  features="console"
  title="index.ts"
  code={`const langs = ["ts", "tsx", "js"];
for (const lang of langs) console.log(lang, Bun.version);`}
/>
```

<Code
  playground
  mode="code"
  features="console"
  title="index.ts"
  code={`const langs = ["ts", "tsx", "js"];
for (const lang of langs) console.log(lang, Bun.version);`}
/>

Since `title` is the file's name, `label` sets the embed's accessible name, the title of its frame (default "Bun playground"): `<Code playground label="Greeting example" … />`. `layout="stack"` puts the preview under the editor instead of beside it: `<Code playground mode="preview" layout="stack" height="auto" … />`.

`mark`, `ins` and `del` mark lines of the block's `code` (not the tabs `files` adds), as `"1,4-6"`, the way [a fence's line marks](#line-marks) do. A `playground` block ignores them:

```mdx
<Code lang="ts" title="server.ts" mark="1" ins="2" del="3" code={`import { Elysia } from "elysia";
new Elysia().get("/", () => "hi").listen(3000);
Bun.serve({ fetch: () => new Response("hi") });`} />
```

<Code lang="ts" title="server.ts" mark="1" ins="2" del="3" code={`import { Elysia } from "elysia";
new Elysia().get("/", () => "hi").listen(3000);
Bun.serve({ fetch: () => new Response("hi") });`} />

`notes` does the same for `<Code>`, with the notes as plain text, the Nth for the `// (N)` comment in `code` (as [a fence's notes](#notes)):

```mdx
<Code lang="ts" notes={["One app holds every route.", "A handler's return value is the response."]} code={`const app = new Elysia() // (1)
  .get("/", () => "hi"); // (2)`} />
```

<Code lang="ts" notes={["One app holds every route.", "A handler's return value is the response."]} code={`const app = new Elysia() // (1)
  .get("/", () => "hi"); // (2)`} />

`files` adds more files. The block gets a tab per file, and the embed opens with the same tabs:

```mdx
<Code
  playground
  mode="code"
  features="console,files"
  title="index.ts"
  files={{ "greet.ts": `export const greet = (name: string) => "Hello, " + name;` }}
  code={`import { greet } from "./greet";
console.log(greet("Astro"));`}
/>
```

<Code
  playground
  mode="code"
  features="console,files"
  title="index.ts"
  files={{ "greet.ts": `export const greet = (name: string) => "Hello, " + name;` }}
  code={`import { greet } from "./greet";
console.log(greet("Astro"));`}
/>

To show a file you keep in the repo, import it as a string with Vite's `?raw` suffix and pass it as `code`. The block stays in step with the file, and the file can be linted, formatted and type-checked like any other. Run starts the block's file; when it isn't an index file, the embed gets a `package.json` whose `main` points at it (it runs but doesn't open as a tab):

```mdx
import { Code } from "@runbun/astro/components";
import wordCount from "../examples/word-count.ts?raw";

<Code playground mode="code" features="console" title="word-count.ts" code={wordCount} />
```

## Fences

With the remark plugin, a fence marked `playground` becomes a runnable block:

````md
```ts playground title="index.ts"
const res = new Response(JSON.stringify({ ok: true }));
console.log(await res.json());
```
````

```ts playground title="index.ts"
const res = new Response(JSON.stringify({ ok: true }));
console.log(await res.json());
```

Consecutive fences with the same `group=<name>` are one example with several files: one block with a tab per fence, and one embed with the same tabs. The first fence's options apply:

````md
```ts playground group=demo title="index.ts"
import { greet } from "./greet";
console.log(greet("Bun"));
```

```ts playground group=demo title="greet.ts"
export const greet = (name: string) => "Hello, " + name;
```
````

```ts playground group=demo title="index.ts"
import { greet } from "./greet";
console.log(greet("Bun"));
```

```ts playground group=demo title="greet.ts"
export const greet = (name: string) => "Hello, " + name;
```

The meta also takes `mode`, `features`, `load`, `height`, `autorun`, `readonly`, `persist`, `theme`, `file`, `path`, `layout` (`layout=stack` puts the preview under the editor, e.g. `playground mode=preview layout=stack height=auto`), `expand` (`expand=false` leaves the modal button out) and `label`, the embed's accessible name (`label="Elysia playground"`; `title` is taken by the file name). Fences without `playground` stay as they were.

`deps` pins the packages a fence installs, in a generated `package.json` that doesn't open as a tab: `deps="elysia@rc,@elysia/openapi@rc,zod@^4"` (a name without a version gets `latest`). In a group the first fence's `deps` applies, and a `package.json` fence of the group's own wins over it. A `package.json` you write, as a fence or in `files`, opens like any other file, unless you mark its fence `hidden`: in a group, a `hidden` fence is a file of the embed but stays out of the block and the tabs (it's never the file Run starts or the one opened, and a group shows at least its first fence). A hidden `package.json` is still the group's, so `deps` and the generated `main` give way to it:

````md
```ts playground group=demo title="index.ts"
import { Elysia } from "elysia";
new Elysia().get("/", () => "hi").listen(3000);
```

```json playground group=demo title="package.json" hidden
{ "dependencies": { "elysia": "rc" } }
```
````

### Every fence

`fences: "all"` makes the plugin render the other fences too, as static blocks like a `<Code>` without `playground`, so a page's code looks the same throughout:

```js
integrations: [runbun({ fences: "all" })],
```

A fence becomes a block only when it can be shown as written. These stay for the site's own highlighter (Expressive Code in Starlight, Shiki in plain Astro):

- meta other than `title` and line marks: `frame=`, `collapse=`, `showLineNumbers`, `wrap`, text or regex marks (`ins="x"`, `mark=/re/`), a range with a space (`{1, 4-6}`) or any other word
- shell languages (`bash`, `sh`, `zsh`, `powershell`, `console`, … the ones Expressive Code draws as a terminal)
- a fence marked `runbun=false`

A fence without a language is plain text. Without a `title`, a file-name comment in the first four lines names the block, as in Expressive Code: the line goes, and an empty line right after it. A path (`// src/index.ts`) or a name with an extension of the fence's kind (`# config.yml` in a YAML fence) counts; `// note` or a URL stays code.

````md
```ts
// server.ts
Bun.serve({ fetch: () => new Response("hi") });
```
````

#### Line marks

`{1,4-6}` (or `mark={1,4-6}`) highlights lines, `ins={…}` marks them as added and `del={…}` as removed, with a `+` or `−` in the gutter. Lines count from 1 and ranges include both ends, as in Expressive Code; lines past the end are skipped. They count the fence as written, a file-name comment included, so the marks stay on their lines when the comment becomes the title:

````md
```ts ins={3} del={4}
// server.ts
import { Elysia } from "elysia";
new Elysia().get("/", () => "hi").listen(3000);
Bun.serve({ fetch: () => new Response("hi") });
```
````

The gutter signs are CSS, so Copy gets the code as written, removed lines included. Screen readers hear "inserted" or "deleted" where the browser supports alt text for generated content. Set the colors with `--runbun-mark-bg`, `--runbun-ins-bg` and `--runbun-del-bg`; by default they come from the code theme.

#### Notes

A comment that is only `(N)` at the end of a line, `// (1)` (or `# (1)`, `<!-- (1) -->`, `/* (1) */`, as the language comments), marks a note when an ordered list follows the fence with one item per marker. Each marker becomes a numbered button at the end of its line, and its item opens next to it as a popover:

````md
```ts
const app = new Elysia() // (1)
  .get("/", () => "hi") // (2)
```

1. One app holds every route.
2. A handler's return value is the response.
````

The comment leaves the code, so Copy gets `const app = new Elysia()` with no marker and no trailing space; the line stays, so line marks keep their numbers. A comment with more in it (`// setup (1)`), or `(1)` inside a string or template literal, isn't a marker. When the markers and the list don't pair up (no list, or one with fewer or more items), both stay as they are and the build prints a warning naming the file. In a browser without popovers the list shows as a list; exported or plain-text views of the page (for Markdown, say) lose the marker numbers but keep the list.

Astro's content cache doesn't track integration options, so after switching `fences` delete `.astro/` (or your build cache) for the pages to render again.

## Playground

`<Playground>` is the embed on its own: `files` are its sources, and its children are the poster shown until it starts. Without children it shows the first file's code. Here `title` is the embed's accessible name (default "Bun playground"), as on `<bun-playground>`. Its other props are the element's options too, e.g. `layout="stack"` for the preview under the editor.

```mdx
import { Playground } from "@runbun/astro/components";

<Playground mode="preview" height="320px" files={{ "index.ts": server }}>
  <p>A server that answers in the preview. Press Run to start it.</p>
</Playground>
```

<Playground
  mode="preview"
  height="320px"
  files={{
    "index.ts": `Bun.serve({
  fetch: () => new Response("<h1>Hello from Bun.serve</h1>", { headers: { "Content-Type": "text/html" } }),
});`,
  }}
>
  <p style="padding: 1rem; margin: 0">A server that answers in the preview. Press Run to start it.</p>
</Playground>

## Options

| Option | Default | |
| --- | --- | --- |
| `playgroundUrl` | `https://runbun.dev/` | Where the embeds come from. |
| `themes` | `["pierre-light", "pierre-dark"]` | The code themes: names of highlights' bundled themes, or Zed or VS Code theme objects. |
| `themeSelector` | | The CSS selector each theme goes under, for a site with its own theme switch, e.g. ``({ name }) => `:root[data-code-theme='${name}']` ``. Without it the first light theme applies, and the first dark one under `prefers-color-scheme: dark`. |
| `sync` | | `{ scheme, family }`: the `<html>` attributes that hold the page's scheme (`light` or `dark`) and theme family, for the embeds to follow. Without it embeds follow the OS. |
| `fences` | `"playground"` | Which fences the remark plugin renders: `"all"` adds every other fence, as a static block ([Every fence](#every-fence)). |

The blocks' look comes from CSS properties you can set: `--runbun-code-border`, `--runbun-code-radius`, `--runbun-code-font`, `--runbun-code-size`, `--runbun-code-caption-size` and `--runbun-code-line-height`.

Every block, a fence's too before you press Run, has a Copy button in its top-right corner (`.runbun-copy`, `[data-copied]` for a moment after a copy). It shows on hover and focus, and always on touch screens. Style it with `--runbun-copy-bg`, `--runbun-copy-fg`, `--runbun-copy-border`, `--runbun-copy-radius` and `--runbun-copy-inset`, or the class:

```css
.runbun-copy {
  --runbun-copy-bg: var(--sl-color-gray-6);
  --runbun-copy-radius: 4px;
}
```

Blocks carry Starlight's `not-content` class, so they work in Starlight pages as they are.
